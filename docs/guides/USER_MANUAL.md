# ユーザーマニュアル

> Discord サーバーをもっと便利に — 「彩加 =Saika=」のすべての機能と使い方

最終更新: 2026年9月23日

---

## はじめに

**「彩加 =Saika=」** は、Discord サーバーの管理・コミュニティ運営をより快適にする多機能 Bot です。
このマニュアルでは、**サーバーメンバー・管理者の両方**の視点から、各機能の使い方をわかりやすく説明しています。

### この説明書の読み方

| -------- | ------------------------------------------- |
| 👤       | **メンバー向け** — 全員が使える機能         |
| 🛡️       | **管理者向け** — 管理権限が必要な設定・操作 |
| ✅       | 現在利用可能な機能                          |

## Botに必要なサーバー権限

「彩加 =Saika=」は **Administrator（管理者）権限を要求しません**。招待リンクにあらかじめ含まれている以下の個別権限を付与してください（招待 URL から導入すれば自動で選択されます）。

| 権限 | 主な用途 |
| -- | -- |
| チャンネルを見る / メッセージを送信 / 埋め込みリンク / メッセージ履歴を読む | 共通（コマンド応答・Embed 表示） |
| メッセージの管理 | メッセージ削除 / 固定メッセージ |
| チャンネルの管理 | チケット / VAC / VC自動募集 |
| ロールの管理 | チケット / リアクションロール / キック系マーカーロール |
| メンバーを移動 | VAC / AFK |
| 接続 | VAC / AFK（移動先VCへの接続。「メンバーを移動」だけでは移動できません） |
| メンバーをキック | 未認証キック |
| サーバー管理 | メンバーログ（招待元トラッキング） |
| スレッドを管理 | メッセージ削除（削除対象に非公開スレッドを選ぶ場合） |
| スレッドでメッセージを送る | Bump リマインダー（スレッド内で Bump された場合の予約パネル・リマインド送信） |

> チャンネル単位の権限上書き（overwrite）で Bot の権限を制限すると、一部機能が動作しなくなる場合があります。操作が失敗する場合は、対象チャンネル・カテゴリで Bot の権限が制限されていないか確認してください。

## 基本コマンド

### この機能でできること

Bot の応答速度確認、コマンド一覧の表示、Bot 自体の情報表示ができます。

### 👤 メンバー向け

#### `/ping` — 応答速度を確認

Bot の API レイテンシーと WebSocket Ping を表示します。Bot が正常に動作しているか確認したいときに使ってください。

#### `/help` — コマンド一覧を表示

Bot で使えるすべてのコマンドを、カテゴリ別（基本・設定・操作）に一覧表示します。
あなただけに見える（ephemeral）メッセージとして表示されるので、チャンネルを汚しません。

> 💡 ユーザーマニュアルの URL が設定されている場合は、Embed 内にリンクも表示されます。

#### `/about` — Bot の情報を表示

「彩加 =Saika=」のバージョンと、公式サイト・この説明書・ダッシュボードへのリンクを表示します。
こちらもあなただけに見える（ephemeral）メッセージです。

> 💡 リンクは設定されているものだけが表示されます。

## ギルド設定機能

### この機能でできること

サーバー全体に適用される共通設定を管理する機能です。Bot の応答言語の切り替え、エラー通知チャンネルの設定、全設定のバックアップ・リストアができます。

### 管理者向け — 設定

#### Bot の応答言語を変更する

```
/guild-settings set-locale locale:en
```

日本語（`ja`）と英語（`en`）を切り替えられます。デフォルトは日本語です。

#### エラー通知チャンネルを設定する

```
/guild-settings set-error-channel channel:#エラー通知
```

イベント駆動の機能（Bumpリマインダー、メッセージ固定、メンバーログ、VC自動募集、VAC）で発生したエラーや、ダッシュボードからのリアクションロールパネル削除時の不整合を指定チャンネルに通知します。未設定の場合、エラーはログにのみ記録されサーバー管理者には通知されません。

**通知される内容の例:**

- メンバーログの参加・退出通知の送信失敗
- メッセージ固定の再送・送信失敗
- Bumpリマインダーの検出・送信失敗
- VC自動募集・VACのチャンネル操作失敗
- リアクションロールパネル削除時にメッセージを自動削除できなかった場合（残ったメッセージの手動削除や Bot の「メッセージの管理」権限の確認が必要）

**💡 ヒント:** サーバー管理者のみが閲覧できるチャンネルを指定することをおすすめします。

#### 現在の設定を確認する

```
/guild-settings view
```

ギルド設定と各機能の設定をページ形式で一覧表示します。セレクトメニューやページボタンで切り替えて確認できます。

#### ギルド設定をリセットする

```
/guild-settings reset
```

言語とエラー通知チャンネルの設定をデフォルトに戻します。各機能の設定（AFK、Bumpリマインダー等）は影響を受けません。

#### 全機能の設定を一括リセットする

```
/guild-settings reset-all
```

ギルド設定を含む全機能の設定を削除します。

**⚠️ 注意:** この操作は取り消せません。実行前に確認ダイアログが表示されます。

#### 設定をエクスポートする

```
/guild-settings export
```

現在の全設定をJSONファイルとしてダウンロードできます。バックアップとして保存し、**同じサーバー**で `/guild-settings import` により復元できます（別サーバーへの移行には使用できません）。

**エクスポート対象:**

- **設定系**: 言語 / エラー通知チャンネル / AFK / Bump リマインダー / VAC / メンバーログ / VC自動募集 / 未承認ユーザー自動キック の各機能設定
- **stateful データ**: チケット設定パネル / open 状態のチケット / スティッキーメッセージ / リアクションロールパネル / VAC が自動作成した VC の追跡情報

> 予約済み Bump リマインダーキュー・closed 済みチケットはエクスポート対象外です（実行時データのため）。

#### 設定をインポートする

```
/guild-settings import file:ファイルを添付
```

エクスポートしたJSONファイルから設定を復元します。同じサーバーでエクスポートしたファイルのみ使用できます。

**マージ方式:**

- **設定系**: ファイルの内容で上書きされます
- **stateful データ**: 現在の DB を優先し、ファイルにあって DB に無いものだけが新規追加されます（既存のチケットやパネルが上書き・削除されることはありません）

実行前に確認ダイアログが表示され、「設定系の取り込み内容」と「stateful の新規追加予定件数」が確認できます。

#### ⚠️ Bot をサーバーから除外する場合

Bot がサーバーからキック・BAN・退出した場合、**そのサーバーの全設定データが自動的に削除されます**。これにはすべての機能設定、チケットデータ、スティッキーメッセージ、Bumpリマインダーなどが含まれます。

設定を保持したい場合は、**Bot を除外する前に `/guild-settings export` で設定をエクスポート**してください。Bot を再招待した後、エクスポートしたファイルで `/guild-settings import` を使って復元できます。

## AFK機能

### この機能でできること

VCに参加中の**他のメンバー**を、指定した「AFKチャンネル」へ素早く移動させる機能です。
「音声に反応がないメンバーを整理したい」といった場面で活躍します。

> **自分を移動する用途はありません。** 少し席を外すだけなら、Discord のミュート・スピーカーミュートで足ります。

### 使い方

#### 他のメンバーをAFKチャンネルへ移動する

```
/afk target-member:@ユーザー名
```

**実行例:**

```
/afk target-member:@田中さん
```

#### VCの参加者全員をAFKチャンネルへ移動する

```
/afk target-channel:🔊ゲーム部屋
```

VC 全員を対象にする場合は、誤操作防止の **確認ダイアログ**（60秒で自動キャンセル）が表示されます。

**⚠️ 注意事項:**

- **`target-member` か `target-channel` のどちらかを必ず指定してください。** 省略して実行することはできません。
- **既定では「メンバーを移動」権限を持つロールにのみ表示されます。** コマンド候補に出てこない場合は管理者に相談してください（→ [`/afk` を使えるメンバーを変える](#afk-を使えるメンバーを変える)）。
- 対象のメンバーが VCに参加していないと移動できません。
- AFK機能が管理者によって有効化されている必要があります。
- AFKチャンネルが設定されていない場合は動作しません。
- 移動の結果は全員に見える形（public）で投稿されます。

---

### 管理者向け — 初期設定

AFK 機能を使うには、まず管理者が AFK チャンネルを設定する必要があります。

#### AFKチャンネルを設定する

```
/afk-settings set-channel channel:#AFKチャンネル名
```

これを実行すると AFK 機能が自動で有効になります。

#### AFKチャンネル設定を解除する

```
/afk-settings clear-channel
```

AFKチャンネルの設定を解除し、AFK機能を無効化します。

#### 現在の設定を確認する

```
/afk-settings view
```

設定中のAFKチャンネルと機能の有効/無効状態が表示されます。

#### `/afk` を使えるメンバーを変える

`/afk` は既定で **「メンバーを移動」権限を持つロール** にのみ表示されます。
この権限を持たないロール（例: 「VC係」）に使わせたい場合は、Bot 側ではなく Discord の機能で許可します。

**サーバー設定 → 連携サービス → 彩加 =Saika= → `/afk`** を開き、対象のロールやメンバーを許可してください。

> この画面に並ぶのは **管理者が上書きした分だけ**で、**Bot 側の既定は表示されません**。何も上書きしていない状態では空に見えますが、既定の制限（「メンバーを移動」が必要）は効いています。
> 設定系コマンドを特定のロールに任せたい場合も、同じ手順で許可できます。

## VC自動作成機能

### この機能でできること

「CreateVC」などの専用チャンネルに入ると、**自分だけの専用VC** が自動で作られます。
全員が退出すると、作られた VC は自動で削除されます。VC を手動で作る手間が省けます。

### メンバー向け — 使い方

#### VCを自動作成する

管理者が設定したトリガーチャンネル（例: `➕ CreateVC`）に入ります。
すると、あなたの専用VC（例: `そのざき's Room`）が自動で作成され、そこに移動されます。

#### 作成したVCの設定を変更する

作成された VC には、**建てた本人に「チャンネルの管理」権限が付与されます**。
VC 名や人数制限は、Discord のチャンネル設定（VC を右クリック →「チャンネルの編集」）から変更してください。

> 同席しているだけのメンバーは変更できません。部屋を建てた本人だけが変えられます。

**💡 ヒント:**

- 名前を変えておくと、どんな集まりか一目でわかります。
- 少人数で話したいときは人数制限を設定しましょう。
- 全員が退出すると VC は自動で削除されます。

---

### 管理者向け — 設定

#### トリガーチャンネルを作成する

```
# カテゴリを指定して作成する
/vac-settings create-trigger-vc category:カテゴリ名

# カテゴリなし（トップレベル）で作成する
/vac-settings create-trigger-vc
```

実行すると「➕ CreateVC」という名前のVCが指定のカテゴリに作成されます。
このチャンネルにメンバーが入ると、自動でその人専用のVCが作られます。

#### トリガーチャンネルを削除する

```
/vac-settings remove-trigger-vc category:カテゴリ名
```

#### 現在の設定を確認する

```
/vac-settings view
```

## VC自動募集機能

### この機能でできること

ボイスチャンネルに**最初の1人**が参加したとき（VCが0人→1人になったとき）、指定したテキストチャンネルへ「通話が始まりました、参加しませんか？」という募集メッセージを自動投稿します。メッセージには **「🔊 VCに参加」ボタン** が付き、クリックするとその VC を開けます。VCから全員が退出すると、ボタンは押せない **「募集終了」** に自動で切り替わります。

> **対象は管理者が明示的に有効化した VC チャンネルだけです。** VC自動作成（VAC）で作られた個人VCは、作られるたびに別のチャンネルになるため対象になりません。CreateVC トリガーチャンネル・AFKチャンネルへの参加でも投稿しません。

### メンバー向け — 募集の見方

- 誰かが空のVCに入ると、**20秒ほど待ってから**指定チャンネルに募集メッセージが投稿されます（最初の1人のときだけ。2人目以降の参加では投稿されません）。
- **間違えて入ってすぐ抜けた場合は投稿されません。** 待っている間に全員が抜けたかどうかを見てから投稿するためです。
- 「🔊 VCに参加」ボタンからその場でVCへ移動できます。
- 通話が終わって全員が抜けると、ボタンは「募集終了」（押下不可）に変わります。メッセージ自体は履歴として残ります。

### 管理者向け — 設定

#### 投稿先チャンネルを設定する

```
/vc-auto-recruit-settings set-post-channel channel:#お知らせ
```

すべての募集メッセージはここで指定した1つのチャンネルにまとめて投稿されます。

> 投稿先チャンネルを削除すると設定は自動的にリセットされ、**エラー通知チャンネルとサーバーのシステムチャンネルへお知らせが届きます**（エラー通知チャンネルは `/guild-settings set-error-channel` で設定できます）。

#### 機能を有効化する

```
/vc-auto-recruit-settings enable
```

> 投稿先チャンネルを先に設定しておく必要があります。

#### 機能を無効化する

```
/vc-auto-recruit-settings disable
```

#### カスタム募集メッセージを設定する

```
/vc-auto-recruit-settings set-message
```

コマンドを実行するとポップアップ（モーダル）が開き、**複数行のテキスト**を入力できます（最大500文字）。本文は通常メッセージとして送信されるため、**ロールメンションや `@everyone` を書くと実際に通知が飛びます**（`@everyone`・メンション不可ロールの通知には Bot に「@everyone・@here・全てのロールにメンション」権限が必要です）。

以下のプレースホルダーが使用できます：

| プレースホルダー    | 内容                          |
| ------------------- | ----------------------------- |
| `{userMention}`     | 参加者のメンション            |
| `{userName}`        | 参加者のユーザー名            |
| `{channelMention}`  | VCのメンション（クリックで開く） |
| `{channelName}`     | VC名                          |
| `{serverName}`      | サーバー名                    |

**入力例:**

```
@通話したい人 {channelMention} で {userName} さんが通話を始めました！
```

> カスタムメッセージを設定しない場合は、デフォルト文（「(VC) で通話が始まりました。参加しませんか？」）が使われます。

#### カスタム募集メッセージを削除する

```
/vc-auto-recruit-settings clear-message
```

#### Embed の表示を切り替える

```
/vc-auto-recruit-settings set-embed enabled:true   ← Embed あり（既定）
/vc-auto-recruit-settings set-embed enabled:false  ← 本文＋ボタンのみ
```

Embed には VC・開始した人が表示されます。Embed を無効にしても、本文（カスタム or デフォルト）と「VCに参加」ボタンは常に投稿されます。

#### 募集する対象 VC チャンネルを設定する（重要）

募集は **有効化した VC チャンネルでのみ** 投稿されます。プライベート/スタッフ用 VC に募集が漏れないよう、**「ここで募集して良い」VC チャンネルだけを明示的に有効化**してください。

```
/vc-auto-recruit-settings add-channel      ← 未登録の VC チャンネルをメニューから複数選択して追加
/vc-auto-recruit-settings remove-channel   ← 登録済みの VC チャンネルをメニューから複数選択して解除
```

どちらもコマンドを実行するとセレクトメニューが表示され、VC チャンネルを複数まとめて選べます。VAC（VC自動作成）のトリガーチャンネルと AFK チャンネルはメニューに表示されません。

- **有効チャンネルが1つも設定されていないと、どこにも投稿されません**（機能を有効化しても未登録のままだと投稿は発生しません）。
- 判定は「VC チャンネル ID が登録済みか」だけで行います。そのため、**認証制サーバーでメンバーにしか見えない VC でも、有効化済みであれば正しく募集されます**。
- VC チャンネルを削除すると、その有効チャンネル設定は自動的に外れます。

#### 現在の設定を確認する

```
/vc-auto-recruit-settings view
```

#### 設定をリセットする

```
/vc-auto-recruit-settings reset
```

VC自動募集の全設定（有効/無効・投稿先チャンネル・Embed設定・カスタムメッセージ・有効チャンネル・追跡中の募集）をデフォルト状態に戻します。確認ダイアログが表示されるので、「🗑️ リセットする」ボタンで確定してください。

> **⚠️ 注意:** この操作は取り消せません。

## メッセージ固定機能

### この機能でできること

チャンネルのルールや重要なお知らせを、**常にチャンネルの一番下**に表示し続ける機能です。
Discord 標準の「ピン留め」は上に固定されますが、スティッキーメッセージは常に最新メッセージの直下に表示されるため見逃されにくくなります。

**主な用途の例:**

- チャンネルのルールやマナーを常に表示
- イベント告知や締め切りを見落とさないように
- 質問チャンネルのテンプレートを常時表示
- 注意事項をいつでも確認できるように

### 管理者向け — 使い方

#### スティッキーメッセージを設定する

**プレーンテキストで設定する:**

```
/sticky-message set channel:#チャンネル名
```

コマンドを実行すると、メッセージ内容を入力するポップアップが表示されます。

**Embed（カード形式）で設定する:**

```
/sticky-message set channel:#チャンネル名 style:embed
```

Embed で設定するとタイトル・説明文・カラーを設定でき、より見やすいメッセージになります。

**使用例:**

```
# ルールチャンネルにプレーンテキストでスティッキーメッセージを設定
/sticky-message set channel:#rules

# お知らせチャンネルにEmbed（緑色）で設定
/sticky-message set channel:#announcements style:embed
```

> コマンド実行後にポップアップが開きます。内容を入力して送信してください。

#### スティッキーメッセージを更新する

```
/sticky-message update channel:#チャンネル名
```

更新内容のポップアップが表示されます。変更したい項目だけ入力してください。

#### スティッキーメッセージを削除する

```
/sticky-message remove
```

コマンドを実行すると、設定済みのチャンネル一覧がセレクトメニューで表示されます。
削除したいチャンネルを選択し（複数選択可）、「🗑️ 削除する」ボタンを押して確定します。
Discord 上のメッセージも同時に削除されます。

#### 設定中のスティッキーメッセージを確認する

```
/sticky-message view
```

このサーバーで設定中のチャンネル一覧が表示されます。チャンネルを選ぶと詳細が確認できます。

**💡 ヒント:** ルールや告知を Embed 形式で作ると、色やタイトルで目を引きやすくなります。

## メッセージ削除機能

### この機能でできること

**モデレーター向け**の機能です。条件を指定してサーバー内のメッセージを一括削除できます。

- 特定ユーザーのメッセージをサーバー全体から一掃（複数ユーザー指定可）
- 特定チャンネルに絞って削除（複数チャンネル指定可）
- キーワードを含むメッセージを絞り込んで削除
- 特定期間（日数・日付範囲）のメッセージを削除
- 投稿者タイプで絞り込み（bot のみ / 人のみ / 既に居ない人〔退出済みメンバー〕のみ）

> **⚠️ 必要な権限**: メッセージ管理（Manage Messages）またはサーバー管理者

---

### 基本的な使い方

#### コマンドオプション一覧

| オプション | 型     | 説明                                                                           |
| ---------- | ------ | ------------------------------------------------------------------------------ |
| `count`    | 数値   | 収集する件数の上限（省略時は最大1000件）                                       |
| `keyword`  | 文字列 | 指定キーワードを含むメッセージのみを対象（大文字小文字を区別しない）           |
| `days`     | 数値   | 過去 N 日以内のメッセージのみ対象（`after`/`before` とは排他）                 |
| `after`    | 日付   | この日時以降のメッセージのみ対象。 形式: `YYYY-MM-DD` or `YYYY-MM-DDTHH:MM:SS` |
| `before`   | 日付   | この日時以前のメッセージのみ対象。 形式: `YYYY-MM-DD` or `YYYY-MM-DDTHH:MM:SS` |

#### 条件設定ステップ

コマンド実行後、**条件設定画面**が表示されます。ここで対象ユーザーや対象チャンネルを選択できます。

| UI 要素                | 説明                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| ユーザー選択メニュー   | 削除対象のユーザーを選択（最大25人、複数選択可）。未選択で全ユーザー |
| チャンネル選択メニュー | 対象チャンネルを選択（最大25個、複数選択可）。未選択でサーバー全体   |
| 投稿者タイプ選択       | 投稿者の種別で絞り込み（全投稿者 / 🤖 bot のみ / 👤 人のみ / 🚪 既に居ない人のみ）。退出済みメンバーのメッセージ一掃に便利 |
| Webhook ID 入力        | Webhook のメッセージを削除したい場合にモーダルから ID を入力         |
| スキャン開始           | 条件を確定してスキャンを開始                                         |
| キャンセル             | 操作を中止                                                           |

> **💡 ヒント**: コマンドオプション（`count`/`keyword`/`days`/`after`/`before`）と条件設定ステップ（ユーザー/チャンネル/投稿者タイプ）を合わせて、最低1つのフィルター条件が必要です。

#### 使用例

```
# 特定ユーザーのメッセージをサーバー全体から削除
/message-delete
→ 条件設定で @BadUser を選択 → スキャン開始

# キーワードで絞り込み → 条件設定でチャンネルを選択
/message-delete keyword:スパム

# 過去7日間 + 件数上限で削除
/message-delete days:7 count:100
→ 条件設定で @Spammer を選択 → スキャン開始

# 日付範囲を指定 → 条件設定でユーザーを選択
/message-delete after:2026-01-01 before:2026-01-31

# 退出済みメンバーのメッセージを一掃
/message-delete
→ 条件設定で投稿者タイプ「🚪 既に居ない人のみ」を選択 → スキャン開始
```

#### 注意事項

- コマンドオプションと条件設定ステップを合わせて、最低1つのフィルター条件を指定してください
- `days` と `after`/`before` は同時に指定できません
- 条件設定ステップは3分以内に操作してください（タイムアウトで自動キャンセル）
- 14日以上前のメッセージは個別削除になるため、件数が多いと時間がかかります
- **この操作は取り消せません**

#### スキャン

コマンドを実行するとスキャンが開始され、進捗がリアルタイムで表示されます。

```
スキャン中... 1200件
対象メッセージを検索中... 12 / 1000件
```

スキャン完了を待たずに収集済みのメッセージでプレビューへ進むには「🔎 収集分を確認」ボタンを押してください。

#### プレビューダイアログ（Stage 1）

スキャン完了後、削除候補メッセージのプレビューが表示されます。

- **フィルター機能** — 投稿者（個別 / bot のみ / 人のみ / 既に居ない人のみ）・キーワード・日付範囲でプレビュー表示を絞り込めます（表示の切り替えのみで、削除対象は変わりません）
- **除外機能** — 削除したくない特定のメッセージを個別に除外できます
- **「削除する」** — 最終確認ダイアログ（Stage 2）へ進みます
- **「キャンセル」** — 操作を中止します

#### 最終確認ダイアログ（Stage 2）

削除対象のメッセージ一覧が再度表示されます。内容を確認してから削除を実行してください。

| ボタン        | 動作                       |
| ------------- | -------------------------- |
| 🗑 削除する   | 削除を実行して完了         |
| ◀ 戻る        | プレビューダイアログに戻る |
| ❌ キャンセル | 操作を中止する             |

#### 削除完了後

削除完了後に削除件数とチャンネル別の内訳が表示されます。

## Bumpリマインダー機能

### この機能でできること

[Disboard](https://disboard.org/) や [ディス速](https://dissoku.net/) の Bump コマンドを自動検知し、次に Bump できるようになる **2時間後**に自動でリマインダーを送信します。
「Bump の時間を忘れてしまう」「誰かが Bump してくれるのを待っている」という状況を解消します。

### メンバー向け — リマインダーを受け取る

Bump が実行されると、Bot からボタン付きのメッセージが届きます。

<table border="1" cellpadding="8" width="420">
<tr><th align="left">ℹ️ Bumpリマインダー機能</th></tr>
<tr><td>
54分後にリマインドが通知されます。
</td></tr>
<tr><td><kbd>🔔 ユーザー通知をONにする</kbd> &nbsp; <kbd>🔕 ユーザー通知をOFFにする</kbd></td></tr>
</table>

- **🔔 ユーザー通知をONにする** — 2時間後のリマインダーで自分に通知が届きます。既にONの場合でもそのまま成功します。
- **🔕 ユーザー通知をOFFにする** — 通知設定を解除します。既にOFFの場合でもそのまま成功します。

**💡 ヒント:** Bumpに協力したいときは「🔔 ユーザー通知をONにする」を押して通知をオンにしておきましょう。

---

### 管理者向け — 設定

#### リマインダーを有効化する

**デフォルトで有効**なので、通常は操作不要です。

```
/bump-reminder-settings enable
```

#### リマインダーを無効化する

```
/bump-reminder-settings disable
```

#### リマインダー時にメンションするロールを設定する

```
/bump-reminder-settings set-mention role:@Bumpロール
```

> **📝 注:** ユーザー個別の通知設定はパネルのボタンから各自が行います。管理コマンドではロールのみ設定できます。

#### メンション設定を削除する

```
/bump-reminder-settings remove-mention
```

#### 通知登録ユーザーを管理する

```
/bump-reminder-settings remove-mention-users
```

パネルのボタンで「🔔 ユーザー通知をONにする」を押したユーザーの一覧を表示し、選択したユーザーを通知リストから削除できます。セレクトメニューで削除対象を選び（複数選択可）、「🗑️ 削除する」ボタンで確定します。「☑️ 全員を選択」ボタンで全ユーザーを一括選択することもできます。

#### 現在の設定を確認する

```
/bump-reminder-settings view
```

#### 設定をリセットする

```
/bump-reminder-settings reset
```

Bumpリマインダーの設定（メンションロール・メンションユーザー・進行中のリマインダー）をすべてリセットします。確認ダイアログが表示されるので、「🗑️ リセットする」ボタンで確定してください。

> **⚠️ 注意:** リセット後も機能自体は有効のままです（Bumpの自動検知は継続されます）。メンション設定のみがクリアされます。

**💡 ヒント:** `@Bump担当` のようなロールを作って設定しておくと、有志のメンバーだけにリマインダーが届くようにできます。

## チケット機能

### この機能でできること

サポート対応用のチケットチャンネルを作成・管理する機能です。メンバーはボタンからチケットを作成でき、スタッフロールを持つユーザーが対応します。

### 👤 メンバー向け

#### チケットを作成する

管理者が設置したパネルの 🎫 **チケットを作成** ボタンを押すと、件名・詳細を入力するモーダルが表示されます。送信すると、あなたとスタッフだけが見える専用チャンネルが作成されます。

#### チケットをクローズする

対応が完了したら、チケットチャンネル内の 🔒 **クローズ** ボタン、または `/ticket close` コマンドでクローズできます。

#### チケットを再オープンする

クローズ済みのチケットを再度開きたい場合は、🔓 **再オープン** ボタン、または `/ticket open` コマンドで再オープンできます。

### 🛡️ 管理者向け — 設定

#### パネルを設置する

```
/ticket-settings setup category:カテゴリ
```

指定したカテゴリにチケットパネルを設置します。モーダルでパネルのタイトル・説明文をカスタマイズでき、スタッフロールを選択します。

> パネルはコマンドを実行したチャンネルに設置されます。**スレッド内では実行できません**。スレッドはアーカイブされると一覧から消えてパネルを見失うため、通常のテキストチャンネルで実行してください。

#### 設定を確認する

```
/ticket-settings view
```

#### パネルを編集する

```
/ticket-settings edit-panel category:カテゴリ
```

#### スタッフロールを管理する

```
# 上書き設定
/ticket-settings set-roles category:カテゴリ

# 追加
/ticket-settings add-roles category:カテゴリ

# 削除
/ticket-settings remove-roles category:カテゴリ
```

#### 自動削除期間を設定する

```
/ticket-settings set-auto-delete category:カテゴリ days:日数
```

クローズ後、指定日数が経過したチケットチャンネルを自動削除します。

#### 同時チケット上限を設定する

```
/ticket-settings set-max-tickets category:カテゴリ count:件数
```

ユーザーあたりの同時オープン可能なチケット数を制限します。

#### パネルを撤去する

```
/ticket-settings teardown
```

選択したカテゴリのパネル・設定を削除します。オープン中のチケットがある場合は警告が表示されます。

**⚠️ 注意:**

- パネルメッセージやパネル設置チャンネルを手動で削除した場合、Bot が自動的に設定をクリーンアップします。
- チケットチャンネルを手動で削除した場合も、対応するチケットレコードが自動的にクリーンアップされます。

**💡 ヒント:** Bot をサーバーから除外する前に、必要なチケットの内容をエクスポートしてください。除外すると全てのチケット設定・データが削除されます。

### 権限について

| 操作             | 必要な権限         |
| ---------------- | ------------------ |
| チケット作成     | なし               |
| クローズ・再オープン | チケット作成者 or スタッフロール |
| チケット削除     | スタッフロールのみ |
| 設定管理         | サーバー管理権限   |

## リアクションロール機能

### この機能でできること

管理者が設置したパネルのボタンを押すことで、ロールを自分で付与・解除できる機能です。自己紹介ロールや通知設定ロールなど、メンバーが自由に選べるロールの運用に最適です。

### 👤 メンバー向け

#### ロールを取得・解除する

管理者が設置したリアクションロールパネルのボタンを押すだけです。パネルのモードによって動作が異なります。

| モード | 動作 |
| --- | --- |
| トグル | ボタンを押すたびにロールが付与/解除されます |
| ワンアクション | ロールが付与されます（解除はできません） |
| 排他 | グループ内で1つだけ選択できます（別のボタンを押すと切り替わります） |

### 🛡️ 管理者向け — 設定

#### パネルを設置する

```
/reaction-role-settings setup
```

以下のステップでパネルを作成します。

1. モーダルが表示されるので、パネルのタイトル・説明文・カラーを入力
2. モードを選択（トグル / ワンアクション / 排他）
3. ボタンを追加（ラベル・絵文字・スタイルを設定 → 割り当てるロールを選択）
4. 「もう1つ追加」で複数ボタンを追加、「完了」でパネルを設置

> パネルはコマンドを実行したチャンネルに設置されます。**スレッド内では実行できません**。スレッドはアーカイブされると一覧から消えてパネルを見失うため、通常のテキストチャンネルで実行してください。

#### 設定を確認する

```
/reaction-role-settings view
```

設置済みパネルの設定一覧を表示します。複数パネルがある場合はページネーションで切り替えできます。

#### パネルを編集する

```
/reaction-role-settings edit-panel
```

パネルのタイトル・説明文・カラーを変更します。

#### ボタンを追加する

```
/reaction-role-settings add-button
```

既存パネルにボタンを追加します（1パネルあたり最大25個）。

#### ボタンを削除する

```
/reaction-role-settings remove-button
```

パネルからボタンを削除します（複数選択可、全削除は不可）。

#### ボタンを編集する

```
/reaction-role-settings edit-button
```

既存ボタンのラベル・絵文字・スタイル・割り当てロールを変更します。

#### パネルを撤去する

```
/reaction-role-settings teardown
```

選択したパネルを撤去します（複数選択可）。パネルメッセージとDB設定が削除されます。

**⚠️ 注意:**

- パネルメッセージやパネル設置チャンネルを手動で削除した場合、Bot が自動的に設定をクリーンアップします。
- パネルのモードは設置後に変更できません。変更が必要な場合はパネルを作り直してください。

**💡 ヒント:** 1ボタンに複数のロールを割り当てることができます。例えば「ゲーマー」ボタンに複数のゲーム関連ロールをまとめて付与することが可能です。

### 権限について

| 操作 | 必要な権限 |
| --- | --- |
| ボタンクリック（ロール操作） | なし |
| 設定管理 | サーバー管理権限 |
| Bot | ロール管理権限・メッセージ送信権限 |

## 未承認ユーザー自動キック機能

### この機能でできること

サーバーに参加してから一定期間内に「認証ロール」を取得していないメンバーを、**事前の警告（本人への DM ＋ 任意で通知チャンネルへの予告）を経て**自動的にキックします。多段階の認証フローのどこかで止まってしまったメンバーの整理を自動化します。

- **判定はシンプル**: 「参加からの経過日数が猶予日数を超え、かつ認証ロールを持っていない」メンバーが対象です。
- **警告を送る前にキックしません**（警告日数を設定している場合）: 警告日数を設定していれば、必ず事前警告を 1 回送り、本来の予告期間（猶予日数 − 警告日数）を確保してからキックします。Bot の停止などで日次チェックが何日か飛んで警告日を過ぎてしまっても、まず警告を送り、キックは次回以降に回します（＝警告なしの不意のキックは起きません）。
- **有効化時点が起算の下限**: 「機能を有効化した時刻」より前の在籍期間はカウントしません。導入直後に古参の未承認メンバーが無警告で一斉キックされることはありません。
- **自動除外**: Bot・サーバーオーナー・**管理者権限**保持者・認証ロール保持者は対象外です。
- **除外ロール**: 任意のロールをキック対象から除外できます。

### 管理者向け — 設定

#### 認証ロールを設定する

```
/unverified-kick-settings set-verified-role role:@一般ユーザー
```

これを持っていればキック対象外となる「認証ロール」です。**設定は必須**で、有効化の前提になります。

#### 猶予日数を設定する

```
/unverified-kick-settings set-grace-days days:7
```

参加からキックまでの猶予日数です（**1〜30日**・デフォルト 7 日）。

#### 事前警告（警告日数）を設定する

```
/unverified-kick-settings set-warn-days days:5
/unverified-kick-settings clear-warn-days
```

参加から何日経過した時点で事前警告を送るかを設定します（**1〜猶予日数-1**・推奨は猶予日数-2）。`clear-warn-days` で事前警告を無効化できます（未設定時は警告なし）。

#### 通知チャンネル／ログチャンネルを設定する

```
/unverified-kick-settings set-notify-channel channel:#認証案内
/unverified-kick-settings set-log-channel channel:#監査ログ
```

- **通知チャンネル**: 事前警告時に「キック予告」（対象メンバー一覧・残日数）を投稿します（スタッフ／メンバー向け）。
- **ログチャンネル**: キック実行・自動無効化の監査ログ（Embed）を送信します（運用者向け）。

2 つは独立して設定でき、**同じチャンネルを指定しても、別々でも、片方だけでも**構いません。各 `clear-notify-channel` / `clear-log-channel` で解除できます。Bot に送信権限（チャンネルを見る／メッセージを送信／埋め込みリンク）が必要です。

#### 対象ロールを設定する（メンション通知）

```
/unverified-kick-settings set-marker-role role:@認証待ち
```

事前警告の通知直前に対象メンバーへ自動付与されるロールです。**認証ロールを取得した時点で自動的に外れます**。Bot に「ロールの管理」権限が必要で、対象ロールは Bot の最上位ロールより下位である必要があります。`clear-marker-role` で連携を解除できます（既に付与済みのロールは一括では外しません）。

#### メンション通知を設定する

```
/unverified-kick-settings mention enable
/unverified-kick-settings mention disable
```

通知チャンネルへの投稿で、対象メンバー全員に個別メンション（`@ユーザー名`）を送るかどうかを設定します（デフォルト: 有効）。メンションが不要な場合は `disable` で無効化できます。

#### タイムゾーン・実行時刻を設定する

```
/unverified-kick-settings set-timezone
/unverified-kick-settings set-run-hour hour:3
```

日次チェックを実行するタイムゾーンと時刻を設定します。`set-timezone` を実行するとタイムゾーンのセレクトメニューが表示されます（デフォルト: `Asia/Tokyo`）。`set-run-hour` は 0〜23 の整数で指定します（デフォルト: 3 時）。

#### 警告 DM のカスタムメッセージを設定する

```
/unverified-kick-settings set-dm-message
/unverified-kick-settings clear-dm-message
```

コマンドを実行するとポップアップ（モーダル）が開き、複数行のテキストを入力できます（最大500文字）。未設定時はデフォルト文が使われます。認証手順やチャンネルへの案内は、この本文に直接書いてください。

**警告 DM で使えるプレースホルダー:** `{serverName}` / `{graceDays}` / `{warnDays}` / `{remainingDays}`（キックまでの残日数）

#### 通知チャンネルのキック予告メッセージをカスタマイズする

```
/unverified-kick-settings set-notify-message
/unverified-kick-settings clear-notify-message
```

通知チャンネルへ投稿される「キック予告」の**本文**をカスタムできます（モーダル入力・最大500文字・未設定時はデフォルト文）。対象メンバー一覧・キック予定日は固定の Embed で表示されます。

**キック予告で使えるプレースホルダー:** `{count}`（対象人数） / `{serverName}` / `{graceDays}` / `{warnDays}` / `{remainingDays}`

> **廃止されたプレースホルダー:** `{markerRole}`（ロール一括メンションを廃止し、メンション通知設定に移行）。既存のカスタムメッセージに含まれていても無視されます。

#### 機能を有効化／無効化する

```
/unverified-kick-settings enable
/unverified-kick-settings disable
```

有効化には認証ロールの設定と Bot の「メンバーをキック」権限が必要です。有効化のたびにキック起算がリセットされます。設定したタイムゾーン・時刻で毎日自動チェックが走ります。

#### キック除外ロールを管理する

```
/unverified-kick-settings exempt add role:@モデレーター
/unverified-kick-settings exempt list
```

除外ロールへの追加は `add`。**削除は `/unverified-kick-settings exempt remove`** を実行すると、登録済みのロールがセレクトメニューに並ぶので、**複数選択して一括削除**できます。登録したロールを持つメンバーはキック対象から除外されます。

#### キック対象をプレビューする

```
/unverified-kick-settings preview
```

現時点でのキック対象・事前警告対象を、経過日数つきで一覧表示します（自分にだけ見える表示・実際の操作は行いません）。

#### 現在の設定を確認する

```
/unverified-kick-settings view
```

#### 設定をリセットする

```
/unverified-kick-settings reset
```

全設定をデフォルト状態に戻します。確認ダイアログが表示されるので、「🗑️ リセットする」ボタンで確定してください。

> **⚠️ 注意:** この操作は取り消せません。

## よくある質問（FAQ）

### AFK機能について

**Q. AFK機能で「機能が無効です」と表示される。**

A. 管理者がまだ AFK チャンネルを設定していません。`/afk-settings set-channel` を実行してください。

**Q. 他のメンバーをAFKに移動できない。**

A. 対象のメンバーがボイスチャンネルに参加していることを確認してください。VCに入っていないと移動できません。

**Q. `/afk` がコマンド候補に出てこない。**

A. `/afk` は既定で「メンバーを移動」権限を持つロールにのみ表示されます。権限を持たないメンバーに使わせたい場合は、**サーバー設定 → 連携サービス → 彩加 =Saika= → `/afk`** から個別に許可してください。

---

### Bumpリマインダーについて

**Q. Bumpしたのにリマインダーが来ない。**

A. 以下を確認してください。

- 「彩加 =Saika=」がサーバーに参加しており、そのチャンネルを閲覧できる権限があるか
- `/bump-reminder-settings view` で機能が有効になっているか
- メンション設定（ロール・ユーザー）が設定されているか、またはリマインダー登録ボタンを押しているか

---

### VC自動作成について

**Q. CreateVC に入ったのに VC が作られない。**

A. 以下を確認してください。

- 「彩加 =Saika=」がチャンネルを作成できる権限（`チャンネルの管理`）を持っているか
- `/vac-settings view` でトリガーチャンネルが正しく設定されているか

**Q. 作成したVCの名前や人数制限を変えたい。**

A. 部屋を建てた本人には「チャンネルの管理」権限が付いているので、Discord のチャンネル設定（VC を右クリック →「チャンネルの編集」）から変更できます。同席しているだけのメンバーは変更できません。

---

### メッセージ固定機能について

**Q. メッセージが最下部に表示されなくなった。**

A. Bot がチャンネルでメッセージを送信する権限があるか確認してください。また、`/sticky-message view` で設定が有効になっているか確認できます。

**Q. スティッキーメッセージを Embed で設定したい。**

A. `/sticky-message set channel:#チャンネル名 style:embed` を実行してください。ポップアップでタイトル・説明・カラーを入力できます。

---

## 多言語対応

「彩加 =Saika=」はサーバーごとに **日本語** と **英語** を切り替えて使用できます。
デフォルトは日本語です。変更するには `/guild-settings set-locale` を実行してください（サーバー管理権限が必要です）。
